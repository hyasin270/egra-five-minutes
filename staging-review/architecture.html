EGRA/EGMA ICT test build: architecture, correctness, robustness, privacy, tests

Reviewer dimension: architecture · correctness · robustness · security/privacy · test quality Code reviewed: origin/staging @ 554c6a8d (snapshot in ../src/ is byte-identical to staging for all 41 touched files; verified with cmp), commits 783116cc → e81dbc03 by Sabeena. Live evidence used: Axiom digital-coach-logs (service digital-coach-staging, 13–27 Sep), read-only analyst queries on the shared Supabase DB, anonymous + presigned HEAD probes of the R2 objects, and a jest run in a throwaway worktree (since removed). Bead: bd-ak1go

Verdict

The shape is sound. It is a flag-gated, coach-marked (Track A only) state machine split into small, single-purpose services, with deterministic stimulus rendering and careful "never hijack" claim guards. The flag-off path is truly inert. But the build does not work end to end on staging today, and it is not safe to promote.

  • Stimulus images never arrive. Every stimulus and passage image points at the private R2 S3 host with no presigning, so WhatsApp gets a 400. Staging logged 3 of 3 failures. The plain-text fallback never fires because the send result is ignored.
  • Listening-comprehension results will be lost. The pilot path is live on staging (the Flow ID is set), but the voicenote migration is not applied. The first voice note a coach sends will make the database reject that subtest's whole insert, and the coach is not told.
  • Letter-ID scoring is wrong. The formula subtracts errors twice and can report negative letters per minute.
  • The table is open. The live table has RLS off while anon/authenticated hold SELECT/INSERT/DELETE. Every sibling assessment table has RLS on.
  • Any ICT teacher can see everyone's rosters. The access gate checks region only, so any of the 53 ICT-region teachers can list every ICT teacher's classes and pull children's names.

Tests are plentiful (132 pass). They cannot catch any of the above: WhatsApp and Supabase are mocked to always succeed, image URLs are checked only for shape, and the voice routing test greps source text.

Coordinator question: what happens to data on staging today, and why the table holds only one row

What recordSubtestAttempt does today when a listening-comprehension voice note has been captured

  1. handleEgraEgmaIctTestVoiceNote always sets whatsappMediaId and recordedAt, even when the R2 upload failed, and sets url when the upload succeeded. It stores these as state.pendingVoiceNote (shared/handlers/egra-egma-ict-test.handler.js:786-791).
  2. After the 6th item is marked, recordQaAnswer passes audioUrl, audioWhatsappMediaId and audioRecordedAt (:446-448).
  3. results.service.js:57-59 spreads each of those into the insert payload whenever it is non-null. So a listening row that has a voice note always carries at least audio_whatsapp_media_id and audio_recorded_at.
  4. None of the audio_* columns exist in the live table. Postgres rejects the statement: an EXPLAIN INSERT … (audio_whatsapp_media_id) run under the read-only role returned ERROR: column "audio_whatsapp_media_id" of relation "egra_egma_ict_test_attempts" does not exist. The whole row is refused, not just the audio columns.
  5. results.service.js:64-69 logs logToFile(..., 'error') plus a persist_failed event containing only error.message and subtestKey. It does not log the scores, the item verdicts or the sessionId. The module doc's claim that it "logs the full result" (results.service.js:15) is false.
  6. The handler ignores the return value (handler.js:434-451), moves on to the next subtest, and later sends "✅ Assessment complete" with the scores from Redis. Then it clears the session (handler.js:338-348). The coach is never told.

What is lost per full administration: both listening-comprehension rows, listening_comprehension_urd (subtest 1) and listening_comprehension_eng (subtest 6). Each loses the coach's 6 item verdicts, the correct and incorrect counts, the audio link and the media id. Once the session is cleared these exist nowhere: not in the DB and not in the logs.

The audio file itself is orphaned in R2 at egra-egma-ict-test/voicenotes/<session_id>/<subtest>.ogg. It can be found only through the separate voice_note_captured event, which does carry sessionId.

The other 12 subtests are written correctly. Their payloads carry no audio_* keys, which is exactly what the conditional spread was designed for. The design protects every row except the one the pilot exists to collect.

TESTING.md is wrong about this. It says the pilot "is fully inert" until both the Flow is registered and the migration is applied (TESTING.md:239-242). The code gates only on EGRA_EGMA_LISTENING_FLOW_ID (handler.js:311). It never checks the migration.

B3. Letter-ID score subtracts errors twice and can go negative

Consequence. Letter-ID fluency is under-reported by twice the error count. A child who read 40 letters with 6 wrong in 60 s gets 28 instead of the standard 34 clpm. A child who is discontinued (0/10) is recorded and shown a negative rate: the test enshrines −27.3/min. This contradicts the team's own research spec, research/01_EGRA_EGMA_structure.md §1.3: Subtask_per_minute = Subtask_score / (Time given − time_remain) × 60, where the score is items correct, and "the child scores zero" on auto-stop. correct is already attempted − incorrect.

Evidence. - shared/services/egra-egma-ict-test/rate-scorer.js:54 const correct = attempted - incorrect; - :56-57 ? (correct - incorrect) / elapsedMinutes // RTI CLPM formula - __tests__/rate-scorer.test.js:46 'handles a 0/10 first-row discontinue without crashing, producing a valid (possibly negative) rate' - :19 expect(result.ratePerMinute).toBeCloseTo(28.0, 5); - The cited source egra_reading_flow_redesign_plan.md §8/§10 (rate-scorer.js:8) does not exist anywhere in the project tree.

B4. The live results table has RLS disabled while anon/authenticated can read, insert and delete

Consequence. The first migration has been applied to the shared prod/staging DB. The table stores children's names (student_identifier) and scores. Its only protection is the secrecy of the Supabase anon key. Every sibling table enforces RLS. This is the class of issue Supabase's security advisor flags as critical.

Evidence. - Read-only query: pg_class.relrowsecurity = f for egra_egma_ict_test_attempts. - has_table_privilege('anon', …, 'SELECT'|'INSERT'|'DELETE') returns t|t|t, and the same for authenticated. - relrowsecurity = t for numeracy_assessments, reading_assessments, students, student_lists and exam_check_sessions. - The migration has no ENABLE ROW LEVEL SECURITY anywhere (database/migrations/pending_egra_egma_ict_test_attempts.sql:26-95). - The live row count is 1, and that row contains a child's name.

Serious

S1. Any ICT-region user (53 of 56 are teachers) can open every ICT teacher's class list and receive a random child's full name

Consequence. The gate is only "flag on AND region ∈ {ict, islamabad, federal}". With the flag on, a teacher typing /egra sees a list of other teachers' names, schools and classes. Tapping one returns a named child from that teacher's roster. This is a cross-teacher disclosure of child PII, and nothing restricts it to coaches.

Evidence. - access-gate.js:45-47 return isFlagEnabled() && isIctRegionUser(user); has no users.role check. Other features do check role, for example NEO on role='aeo'. - roster.service.js:53-62 selects id, name, school_name, phone_number, region, student_lists (…, students ( id, student_name, roll_number, is_active )) for .in('region', Array.from(ICT_REGION_TAGS)), with no user_id scoping. - Live DB: the ICT-region roles are teacher 53, coach 1, school_leader 1, cluster_coordinator 1. Seven classes and 41 active children are reachable today.

S2. The coach can get trapped; /cancel and every other command is swallowed

Consequence. Three phases ignore /cancel: - In awaiting_student_name, /cancel (or /egra, /menu) becomes the child's name and the assessment starts under that name. - In awaiting_wrong_items and awaiting_stopping_point, /cancel gets "'/cancel' is not a number".

In every other phase, all slash commands except /cancel|/stop|/quit get "Please use the buttons above". So /menu, /status, /reading test and /egra are all dead for the life of the session, which is a 1 h sliding TTL. The hook runs before /menu (text-message.handler.js:2143). This breaks the repo's own convention: the numeracy and Support-Assistant guards deliberately let slash commands fall through (text-message.handler.js:370-391, "slash commands fall through so the user can always escape").

Evidence. - handler.js:506-507 case 'awaiting_student_name': { state.studentIdentifier = text.trim() || 'Unnamed student'; - :513-517: the parse failure only re-prompts. - :539-546: the /cancel regex lives only in default. - text-message.handler.js:827: the EGRA hook sits ahead of /menu, /status and /reading test.

S3. The voice note is effectively mandatory, and the reminder copy is wrong

Consequence. Once the Flow is submitted, the only ways forward are to send some voice note or /cancel the whole assessment. That is contrary to "a failed voice-note capture must never block the actual assessment" (handler.js:752-754). Typed text in awaiting_voice_note or awaiting_listening_flow gets "Please use the buttons above", but no buttons exist in those phases. In all 4 real Flow-path sessions, the tester stopped exactly here.

S4. Children's voices and names leak into the general AI pipeline whenever the EGRA claim misses

Consequence. The voice guard claims audio only in awaiting_voice_note. Any other child recording falls through to the normal voice route, where it is uploaded under audio/<phone>/…, transcribed by Soniox, stored in conversations, and answered by GPT. That covers: - a recording sent before tapping "Ready to record" (awaiting_listening_flow), - a retake after the first was captured (item_qa_in_progress), - anything after TTL expiry or a Redis blip (S12).

This contradicts TESTING.md's "No SpeechAce, no Soniox … nothing". Typed names follow the same path. The bd-eg7st commit documents a child's name ("Sameer") going to GPT-5.4-mini when the gate failed. Every typed manual-path name is also written to Axiom.

S6. English ORF scores punctuation marks as words

Consequence. The English passage has 60 words but 68 "items". The 8 full stops and commas are numbered cells that the child "reads correctly", which inflates cwpm and attempted counts by up to 13%. The Urdu passage is unaffected: its punctuation is attached to the words.

Evidence. - item-bank.service.js:50 items: ITEMS.egra.oral_reading_fluency.eng.tokens, item_count: ITEMS.egra.oral_reading_fluency.eng.token_count - Item bank: token_count 68, word_count_excl_punctuation 60, and the tokens include '.' ×7 and ',' ×1 (for example ['Imran','woke','up','early','for','school','.', …]).

S7. Timing and discontinue rules don't follow the instrument

Consequence. There is no 60 s cap and no "time remaining". The rate uses server Start→Stop time, so a late Stop tap (75 s) deflates the score by 20%. At the same time the caption tells the coach to "please self-time this".

The Discontinue button always records items 1–10 as wrong, for every grid. The rules it should follow are: - ORF: the item bank has no discontinue rule for ORF at all. - Familiar words: the instrument rule is "0-1 correct on the first row", so a child who got 1 right is recorded as 0. - Research spec: the first 5 items for word grids.

Evidence. - handler.js:582-583 state.pendingElapsedSeconds = Math.max(1, Math.round(elapsedMs / 1000)); (no upper bound) - :354 const elapsedSeconds = state.pendingElapsedSeconds || 1; - :596 wrongItemNumbers: Array.from({ length: firstRow }, (_, i) => i + 1) - :149 please self-time this - Item bank: familiar_word_reading.urd.discontinue_rule = "If the child scores 0-1 correct on the first row (items 1-10)…"

S8. Reading comprehension ignores how far the child read, and has no "not asked / no response" option

Consequence. After a discontinued or partial ORF, every comprehension question still has to be marked, and the only choices are Correct and Incorrect. Unasked questions become Incorrect. The research spec requires "Incorrect vs no-response must be distinguished at item level".

Evidence. - item-bank.service.js:65,69 set gatedOnGrid: 'orf_eng'|'orf_urd', but gatedOnGrid is never read anywhere in handler.js (grep: zero hits outside item-bank.service.js). - Item bank reading_comprehension.*.response_options = ['Correct', 'Incorrect'].

S9. The roster pick is not persisted, so results can't be tied to a child record, and the existing selection service was not reused

Consequence. The chosen student's id lives only in Redis ("kept for potential future use"). The DB gets the name only, and names are not unique. The live row from a roster-picked session has student_id = NULL, although the column exists with an FK.

Random pick with replacement means the same child can be drawn repeatedly, and absent children can be drawn. The repo already has shared/services/reading/student-selection.service.js (bd-2203/2206): a coverage "staleness ladder", a present-today filter, an injectable RNG, and the reading_assessments.student_id FK pattern. The migration comment still says "This build does not integrate with the students/student_lists roster at all".

S11. Any persist failure is invisible to the coach and unrecoverable

Consequence. The problem goes beyond B2. The grid path tells the coach "Recorded: 18/20 correct…" whether or not the insert succeeded, and the summary always says "✅ Assessment complete". The failure log omits the scores and the sessionId. Nobody, whether coach, operator or data team, can reconstruct a dropped row.

S12. Redis blips cause the session to vanish and come back (and split-brain across replicas)

Consequence. The Redis client uses enableOfflineQueue: false, so during a blip every command fails at once. getState then falls back to a per-process Map that is empty for this coach. Buttons reply "No active assessment session", and typed answers such as "3,7" drop through to general chat. Writes during the blip go to memory only. When Redis recovers, the old state reappears.

With more than one web replica, the memory fallback is per replica. I could not see the replica count from the repo (see Unverified).

Evidence. - session-state.service.js:28-36 falls back to memoryStore.get(phone) || null on any Redis error. - railway-redis.service.js:63 enableOfflineQueue: false

Done well

  • The flag-off path is genuinely inert and cheap. Every entry point checks the gate before touching Redis (handler.js:459, 559, 629, 762). The flag is read fresh per call (access-gate.js:25-27), and tests cover text, button, list and voice with the flag off.
  • The build cannot show an unvalidated AI score. It is coach-marked only (Track A), with no vendor calls in the EGRA path. rumi_auto_score_status is pinned by a CHECK constraint, verified live.
  • The stimuli are rendered deterministically, not AI-generated. They use the exact item-bank Unicode, an embedded Nastaliq font (no network), and a bidi fix for "1." in RTL grids. A round-trip test (buildGridHtml ↔ extractItemsFromHtml vs the item bank) proves the pixels come from the right text. All 7 objects exist in R2. Only the delivery is broken.
  • Voice notes are stored privately. The bucket is private (anonymous GET → 400), and the key egra-egma-ict-test/voicenotes/<session_id>/<subtest>.ogg contains no phone number or name.
  • The Flow-completion handling is defensive.
  • Completion is matched on both phase and session_id, so a stale card cannot drive the session (handler.js:715-726).
  • The detectFlowType rule is narrow, sits before the greedy session_id fallbacks, and has false-positive tests (flow-type-detector.js:112).
  • The voice claim guard returns null unless the session is in the exact phase, so numeracy and coaching routing are unaffected otherwise.
  • Bad input degrades gracefully.
  • The input parser never throws and re-prompts on bad input.
  • The stopping point is bounded to the grid size.
  • The scorer rejects a zero elapsed time instead of producing Infinity.
