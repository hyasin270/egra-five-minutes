reading_assessments already holds what an EGRA row needs: passage_type, passage_text, audio_url, audio_duration_seconds, num_speakers_detected, transcript_text, word_timestamps JSONB, words_read, words_correct, wcpm, accuracy_percentage, time_elapsed_seconds, pronunciation_data JSONB, errors JSONB (omission/substitution/insertion/repetition with position), self_corrections_count, grade benchmarks, on_track. Migration bd-2716 added aser_session_id, content_source ('generated'|'aser_fixed'), and the HITL pair rumi_level / rumi_label / rumi_comprehended vs coach_level / coach_user_id / coach_reviewed_at / rumi_coach_delta; bd-2735 added aser_scored_by ('rumi'|'enumerator'); bd-2720 added aser_ladder_node.

numeracy_assessments (migration 063) already has the same two-column discipline for math: auto_grade_result / auto_grade_confidence / auto_grade_extracted_answer vs human_confirmed_result / human_confirmed_by / human_confirmed_at, discrepancy_flag, recognition_audio_url, computation_photo_url, cost columns.

aser_sessions (bd-2716, bd-2732) = user_id (coach), student_id, student_name, grade_level 1–5, school_id, region, status, completed_at. aser_results_flat (bd-2746) is the analyst view: one row per session with the final level per subject = COALESCE(coach_level, rumi_level).

The ASER ladder (shared/services/aser/aser-ladder.js)

Per subject a directed graph of nodes with pass/fail targets, fixed content (aser-content-bank.js), PASS_THRESHOLD = 80: - Local literacy (Urdu): LOCLIT_LETTERS → LOCLIT_WORDS → LOCLIT_SENTENCES → LOCLIT_STORY (story has three outcomes: struggled / fluent-no-comprehension / fluent-comprehended). Kiswahili variant starts at Sentences. - English literacy: ENGLIT_CAPITAL → ENGLIT_SMALL → ENGLIT_WORDS → ENGLIT_SENTENCES. - Numeracy: NUM_DIGIT_1_9 → 10_99 → 100_999 → NUM_SUB_2D → NUM_SUB_3D → NUM_DIVISION → NUM_FRACTIONS (bd-2743), numbers by audio, computation by photo (NumeracyVisionService), batteries of 3 problems (pickBattery). - isOnTarget(subject, grade, level, comprehended) gives the grade-target verdict.

The coach region-flow samples 3–5 students round-robin across a school's student_lists (aser-student-sampling.service.js, default 5) and requires a real class list (bd-2764/2766). Roles allowed: aeo, training_manager, coach, cluster_coordinator (bd-2749/2762).

What this means for the EGRA product

  • Schema: zero new tables are needed for v1. aser_sessions + reading_assessments + numeracy_assessments already carry session, per-child identity, audio URL, transcript, word timestamps, per-word errors, the AI-vs-coach pair, and who-scored. An EGRA subtask = one reading_assessments row with a new passage_type value (letter_grid, nonword_grid, word_grid, orf, listening_comp) and content_source='egra_fixed'; math subtasks = numeracy_assessments rows. Per-item coach corrections fit errors JSONB / pronunciation_data JSONB with a coach_verdict field, or one new JSONB column coach_item_edits (Rule 15: defend it).
  • Scoring: the alignment engine exists (FluencyService.alignWords + calculateTimeElapsed from Soniox word timestamps). What is missing is (a) a 60-second window cut from timestamps with the toolkit formula score / (60 − time_remaining) × 60, (b) stop-rule logic, (c) per-item confidence for Urdu letters/nonwords (needs the forced-aligner/GOP layer from research/02), (d) a per-item HITL form instead of a per-subject level override.
  • Loop: the v3 sequential-reading day-session (sequential-reading.service.js, pick / auto-pick / attendance / next-or-end, bd-2350 fix) and the ASER sampler (aser-student-sampling.service.js) are the "5 children" loop already built; the EGRA flow reuses them.
  • The one-rung-per-message shape is the thing to kill. The Probe-1/2 evidence (../probes/) shows a single continuous recording per block can be segmented by STT timestamps and labelled by the LLM, so the coach records once per block, not once per item.
  • Where it runs: for NIETE (the "after /observe" ask) the feature lands in Orenda-Project/NIETE-Rumi, which has the observe stack but not the ASER tool or the sequential-reading loop — those must be ported (see research/04 §8 and the "code ported but dependency wasn't" warning). For Rawalpindi/PK it lands in the main bot where the ASER tool already lives.
