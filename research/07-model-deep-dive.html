07 — Model deep dive: what fits better for scoring 6–11-year-old Pakistani children (Urdu + English reading, spoken maths), Sep 2026

Written: 2026-09-15 · Builds on: 02_model_landscape.md (vendor/API tables — not repeated here). Method: primary sources fetched today (arXiv, ISCA archive, ACL Anthology, Hugging Face model cards and the HF model API, vendor docs, GitHub). Every claim carries a URL; anything I could not confirm against a primary page is marked unverified. Cost arithmetic ("≈") is mine, based on 206 recordings × 20 min = 68.7 h of audio.

Input constraints assumed throughout: WhatsApp voice notes (16 kHz Opus) and SurveyCTO audio audits (8 kHz AAC, ~12 kbps); ~5-min child battery inside a ~20-min enumerator recording; a coach corrects the pre-score (HITL), so the target is high-recall flagging with calibrated confidence, not autonomous scoring.

0. What changed since the first report (the six findings that move the plan)

# Finding Why it matters
1 An open, MIT-licensed, EGRA-specific child ASR model now exists — AI-for-Education/sw-tz-child-egra-fastconformer-ctc-110m (Kiswahili, Tanzania, FastConformer-CTC, val WER 13.0 / test WER 16.8, letters 3–18 % WER, syllables 19–23 %, "as little as 50 hours of child-speech data" made the difference) (model card). Built by Zevo Tech / Fab Inc / Laterite / Stellenbosch for the Digitisation-of-EGRA project. It is the recipe we should copy for Urdu (and reuse directly for TZ): a small CTC model fine-tuned on real child EGRA audio, per-subtask WER reported. It also gives us a public yardstick: ~13–17 % WER on child EGRA speech is the realistic bar.
2 Meta Omnilingual ASR (Nov 2025) is Apache-2.0 and lists urd_Arab, urd_Latn, pnb_Arab, hin_Deva, swh_Latn (lang_ids.py, repo, HF card). CTC sizes 300 M / 1 B / 3 B / 7 B; 7B-LLM needs ~17 GiB VRAM; inputs must be < 40 s. Replaces MMS-1b-all (CC-BY-NC, a production blocker flagged in §B of the first report) as the permissive Urdu CTC backbone for forced alignment and CTC-GOP. Per-language Urdu CER is in the repo's CSV but I could not read it today — unverified.
3 Two 2026 Urdu Whisper fine-tunes beat every number in the first report: emads/whisper-large-v3-urdu-v2 (Aug 2026, Apache-2.0): FLEURS-ur 16.65 WER, Common Voice 15.98, Roman-Urdu CER 14.7, code-switch benchmark 35.4 WER, three output registers (Urdu script / Roman / mixed) via control tokens, trained only on CC-0/CC-BY data (Common Voice, IndicVoices, Kathbath, PRUS, MUCS Hinglish) (card); awaaz-se-alfaaz/whisper-turbo-v3-urdu (LoRA on large-v3-turbo, LaTeLL 2026, Apache-2.0): FLEURS 24.07→16.86, CSaLT 27.51→20.77, CV-23 37.23→25.78, real-world YouTube 25.33→24.20 (→21.75 with Gemma3-12B post-edit) (card). The "WER ~26 on CV" baseline from the first report is stale; open Urdu ASR is now ~16–17 WER on read adult speech, on a par with Scribe's 14.4 FLEURS claim, and self-hostable. The 35 % code-switch figure is the number to worry about for maths items.
4 Common Voice 26.0 (June 2026) Urdu = 95.5 h total / 88.5 h validated / 1,127 speakers / 40,385 clips; 10.2 % of clips from "teens", 0 % under-13 (cv-corpus-26.0 JSON). Hindi 436 h, Swahili 157 h in the same file. Confirms there is no public Urdu child speech at all; our 206 recordings are the only Urdu child-EGRA audio anyone has.
5 Gemini timestamp drift is a documented, unanswered bug, not our artefact. Google forum thread (opened 7 Mar 2026, still open 13 Aug 2026): Gemini 3 Flash compresses an 11:49 file into 0:00–9:14 (clock ~22 % fast, −157 s at the end); 3.1 Pro drifts −16 s non-linearly; only the Flash-Lite variants stay < 9 s; workarounds = 5-min chunks, two-pass (Lite for time, Pro for text), disable thinking (thread). The 2026 temporal-grounding literature says the same of every LALM (TAG-Bench best mIoU 31.2, recall@IoU≥0.7 only 21.5 %) (TAG-Bench, TEMPO). No audio LLM returns trustworthy word timestamps natively in Sep 2026. Timestamps must come from a CTC/attention aligner; the LLM only ever sees ≤5-min segments.
6 The hard case is exactly ours, and it is much harder than the MyST numbers suggest. Dutch grade-3 readers recorded "in diverse, noisier environments" (DART) gave 70.4 % WER for the best fine-tuned Whisper-medium vs 5.5 % on clean JASMIN; the authors' fix is utterance-level prompt matching — where ASR output equals the read prompt exactly, precision is 98.3–99.3 %, covering 18–42 % of utterances (Lathouwers et al. 2026). Design the HITL around this: auto-accept only exact matches, route everything else to the coach with the aligner's evidence. Expect the Urdu struggling-reader tail to look like DART, not MyST.

Reading of this for us. (a) Small models fine-tuned on in-domain child audio beat big zero-shot models; whisper-small/medium or a 110 M FastConformer is the right size, not large-v3. (b) Age 6–8 will run ~2× the WER of age 9–11 whatever we do — report by grade. (c) Cross-corpus transfer is poor, so a MyST-trained English model will not save us; we need our own audio in the training mix. (d) The 8 kHz SurveyCTO channel is a first-order problem: run the eval separately on WhatsApp-16 kHz vs SurveyCTO-8 kHz.

1.2 Public child-speech fine-tunes on Hugging Face (Sep 2026)

From the HF model API (search=child, ASR pipeline): the useful ones are the Kiswahili EGRA FastConformer (above), AlexXu811/child-adult-joint-asr-diarization (Whisper, Jan 2026 — joint child/adult ASR + diarization, relevant for enumerator/child separation), dysata/Wav2Vec2-Ru-Child, tartuNLP/xls-r-300m-et-children, kawchar85/ASR_Bangla_Child_Voice (the only South-Asian child ASR checkpoint on the hub; no card metrics), Korean/Estonian/Dutch/Icelandic child Whisper fine-tunes (HF API listing). No Urdu or Hindi child ASR checkpoint exists on the hub. bookbot/wav2vec2-adult-child-cls is a ready adult/child classifier useful for segmenting enumerator vs child turns (card).

1.3 South-Asian child-speech work

  • ASER (Pratham) dataset: 5,301 children 6–14, 81,658 clips, Hindi/Marathi/English, expert level labels not transcripts — still the only large Indian child reading corpus; not public as audio (arXiv 1912.04381).
  • HiACC (2025): first Hinglish adult + child code-switched corpus — 1,858 child segments, 5.24 h total, Zenodo (Data in Brief, PMC). Tiny, but it is the nearest public sample of South-Asian children code-switching — use for a sanity probe on maths items.
  • Google Read Along / Bolo: on-device, Hindi + Urdu + English, product claims only ("64 % improved in 3 months"); no technical report or API (Wikipedia, Slashdot 2019).
  • AI4Bharat / Bhashini / EkStep / Karya: no child-speech evaluation of IndicConformer or IndicWhisper found in any search; IndicVoices is adult (23.7 k h collected, 11.2 k h transcribed as of Dec 2025) (IndicVoices). "Aksharajaani" returned nothing — unverified that it exists as a speech product.
  • Malay/Tamil (Singapore, 2025): 654 P1–P2 children recorded in classrooms; fine-tuned ASR → objective metrics → GPT classifier beat GPT-4o-audio direct (arXiv 2505.19671) — the closest published design to what we are building, in a Tamil-script language.
  • No Pakistani child corpus: searches over CLE/FAST/NUST found only adult UrduSER, UrduSpeech (156 h, adult) and a preschool narrative-skills dataset (audio not for ASR) (UrduSpeech, UrduSER).

Evaluation gotchas specific to Urdu. (1) Script/romanisation inflation: SN-WER transliterates reference and hypothesis to one canonical script before scoring and removes up to 12 % of "model gap" on FLEURS and 67 % of artificial romanisation-induced WER — adopt it, because children and enumerators mix scripts and the ASR may emit Roman islands (arXiv 2606.02548). (2) Diacritics: Urdu text omits short vowels; normalise by stripping U+064B–U+0652 on both sides before alignment (standard practice in the Urdu survey, arXiv 2411.14493). (3) Numerals: Urdu digits are U+06F0–U+06F9 (۰–۹), not Arabic U+0660–U+0669 (٠–٩); the glyphs for 4/5/6/7 differ by locale, and the Urdu forms "are not encoded separately from the Persian variants" (Wikipedia). Map both ranges to ASCII before scoring maths. (4) Code-switching: 35 % WER on the emads code-switch benchmark and seamless-class models that translate instead of transliterate (WER-We-Stand) mean English numbers inside Urdu answers are the single biggest transcript risk — keyterm/hotword biasing (Deepgram, Soniox) and the emads mixed-register token are the two mitigations to test.

Practical recipe (Urdu letter sounds, phoneme awareness, nonwords) and hardware. 1. Segment the enumerator recording into child turns with bookbot/wav2vec2-adult-child-cls + Silero VAD (CPU). 2. For each 10-letter row: (a) ZIPA-large-CR-CTC → IPA hypothesis; (b) Omnilingual omniASR_CTC_1B (urd_Arab) → CTC posteriors → alignment-free CTC-GOP against the expected letter-sound sequence with substitution clusters (Parikh 2025). Score = per-item GOP + IPA edit distance; flag when the two disagree. 3. Reference phones: espeak-ng ur via phonemizer for letter names; hand-written table for letter sounds (short vowels are unrecoverable from text — the table must list allowed variants, e.g. /ə/ vs /a/). 4. Hardware: ZIPA-large (300 M) and omniASR-CTC-1B are single-forward CTC models; on a Modal L4 ($0.80/h) a 5-min clip should take well under a minute — RTF not published for either; benchmark before committing. The whole 206-recording set ≈ 69 h audio ≈ 3–7 GPU-hours ≈ $3–6 of L4 time per model pass (my estimate). 5. Keep MMS_FA only for offline research (CC-BY-NC).

Answer to "is there a model that returns trustworthy word timestamps natively?" Among audio LLMs, no. The only native word timestamps come from ASR models (Gemini 3.5 Transcribe — no Urdu; Voxtral/Qwen3-ASR — no Urdu; whisper-1 API; Soniox/Deepgram/Scribe/AssemblyAI-U2 — Urdu yes) or from CTC/DTW alignment on a self-hosted model (CrisperWhisper 30 ms; Omnilingual/IndicMFA). Our 20–75 s drift on a 17-min file with Gemini 2.5 Pro is consistent with the public bug on 3.x. Rule for the harness: any LLM audio call gets a ≤ 5-min segment plus reference text, and its time references are ignored in favour of aligner timestamps.
